Game-Engine개발 중 2023.03 시작 · 2025.12 재시작 · 커밋 138 · C++ 3.0만 줄

Engine이 Worker 4개(World · Render · RHI · Asset)와 Task Worker 4개를 띄우고, FrameGate 두 개로 Thread 사이 간격을 최대 3프레임으로 제한함. 입력은 lock-free 3중 버퍼로 World Thread에 넘김.

Threading & 프레임 동기화 →

ECS 위에 Scene · Commander를 얹은 Layer. ProxyComponent는 Dirty 표시만 하고, Scene::Flush가 바뀐 것만 스냅샷을 떠서 람다로 Render Thread에 넘김 — World 코드엔 렌더 타입이 한 줄도 없음.

WorldContext 구조 →

RenderScene(SceneProxy · MeshBatch)과 RenderGraph(Transform → Shadow → Geometry → Lighting → Debug)로 구성. (mesh, material) 조합 하나당 Draw Call 하나, Instance 행렬은 Compute Pass가 GPU에서 계산함.

RenderGraph Pass 흐름 →

그래픽스 API를 부르는 유일한 Layer. CRTP Command로 기록하고 RHI Thread가 실행하며, 백엔드는 RHIContext 뒤의 GLContext · VulkanContext로 갈림. Vulkan 메모리는 Container의 TLSFArena로 서브 할당.

Vulkan · RHI 재설계 →

요청은 AssetSystem 큐로, 파싱은 유휴 TaskWorker 4개가, GPU 업로드는 명령만 기록해서 RHI Thread로 넘김. OBJ · MTL · PNG(16비트 포함) · GLSL(#include 펼침) 지원.

라이브러리가 엔진 안에서 실제로 쓰이는 지점

RenderGraph : ECS::Graph ECS가 System 실행 순서를 정할 때 쓰는 위상정렬(Kahn)을 그대로 상속해서, Transform → Shadow → Geometry → Lighting → Debug Pass 순서를 정함.
VulkanArena : TLSFArena Container의 TLSF 할당기를 상속 — 4MB VkDeviceMemory 블록 안을 O(1)로 서브 할당함. 리소스마다 vkAllocateMemory를 부르지 않음.
RenderCommandList World Thread가 기록하는 람다를 Container의 LinearArena 두 개에 번갈아 placement-new — 프레임마다 Reset만 해서 힙 할당이 거의 없음.
PROPERTY → GC World의 Registry/Container 멤버를 Reflection의 PROPERTY로 등록 — Memory의 GC가 그 Property 목록을 따라가며 Entity · Component · Node의 도달 가능성을 마킹함.

각 상세 페이지 앞부분엔 구조와 설계 이유, 실제 커밋 기준 개발 히스토리를 정리해둠. 2026.08 전체 코드 리뷰에서 찾은 버그는 GitHub 이슈로 올린 뒤 대부분 바로 고쳤고, 페이지 안 "버그" 섹션에 원인과 함께 남겨둠.
